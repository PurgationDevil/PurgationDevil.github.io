### 碎尸？缝合？

拿到程序后首先就是看汇编，像这种级别的混淆反编译和任何的自动化工具在当时几乎都是没有用的。

```assembly
start:
sub     rsp, 28h
jmp     loc_1800136A2
endp
```

`start` 函数只有跳转，跟进去看看

```assembly
call    sub_18000853F
jmp     loc_1800340C9
```

这里只调用了一个函数，继续跟进 `jmp`

```assembly
add     rsp, 28h
jmp     nullsub_2
```

`null` 注意

```assembly
nullsub2	proc near
			retn
nullsub2	endp
```

这是一个标准的 “什么都不干、直接返回” 的空函数。由于这里已经形成了函数，所以选择 `nullsub2`，并 Delete function。

然后把这里加一个 `start` 调用该函数的说明（append function tail...）。这样再切换图形界面就好多了。

```assembly
; FUNCTION CHUNK AT .text:00000001800136A2 SIZE 0000000A BYTES
; FUNCTION CHUNK AT .text:0000000180016D82 SIZE 00000001 BYTES
; FUNCTION CHUNK AT .text:00000001800340C9 SIZE 00000009 BYTES
```

修复完成后，IDA 成功识别到：这个 `start` 函数并不是一段连续的代码，它被出题人**活生生肢解成了散落在内存各处的 3 个独立代码碎片**

现在，第一个函数 `start` 修复完毕。虽然是被分成几个小块，但是经过了上面的修复已经成功的在图形界面中可以完整的显现从来一个完整的函数。这就是恐怖的混淆技术：**代码碎尸**。

下面继续分析 `start` 函数调用的唯一函数 `sub_18000853F`。

与整理前的 `start` 一样，这个函数同样是分成了无数碎尸。

从上面分析的经验以及这次的 `jmp` 跳转跟进，很显然 IDA 已经很尽力把这些碎尸合并了。

`jmp` `jmp` `jmp`，在 `sub_18000853F` 下的 `sub_180034E4F` 独立成函数了。

由于每条指令都被破坏和移动，它可能有自己的独立代码块。

把 `sub_180034E4F` 函数 Delete function 然后 append function tail... 这样就又会多一个分析成功的函数。 

但是这样太慢了。

**首先，去除自动分析**。这样才能使用我们自己的脚本进行重分析。（分析到 retn 为至算一个函数）

在 Options $→$ General $→$ Kernel option 的 Options 1 中关闭 Create function tails

并回到 `start` 函数删除函数，这样就完全回到了起点。这样以后再使用脚本。（IDA_pro 才可以使用脚本功能）

# Function Stitcher

import idc, idaapi, idautils
import copy

# ---------------------------------------------------------------------------
# Conditional jump (Jcc) instructions
JCC_INSTRUCTIONS = set(
    (idaapi.NN_ja, idaapi.NN_jae, idaapi.NN_jb, idaapi.NN_jbe, idaapi.NN_jc, 
     idaapi.NN_je, idaapi.NN_jg, idaapi.NN_jge, idaapi.NN_jl, idaapi.NN_jle, 
     idaapi.NN_jna, idaapi.NN_jnae, idaapi.NN_jnb, idaapi.NN_jnbe, idaapi.NN_jnc, 
     idaapi.NN_jne, idaapi.NN_jng, idaapi.NN_jnge, idaapi.NN_jnl, idaapi.NN_jnle, 
     idaapi.NN_jno, idaapi.NN_jnp, idaapi.NN_jns, idaapi.NN_jnz, idaapi.NN_jo, 
     idaapi.NN_jp, idaapi.NN_jpe, idaapi.NN_jpo,  idaapi.NN_js, idaapi.NN_jz))

CALL_INSTRUCTIONS = set((idaapi.NN_call, idaapi.NN_callfi, idaapi.NN_callni))

LOOP_INSTRUCTIONS = set(
     (idaapi.NN_loopw,        idaapi.NN_loop,   
      idaapi.NN_loopd,        idaapi.NN_loopq,  
      idaapi.NN_loopwe,       idaapi.NN_loope,  
      idaapi.NN_loopde,       idaapi.NN_loopqe, 
      idaapi.NN_loopwne,      idaapi.NN_loopne, 
      idaapi.NN_loopdne,      idaapi.NN_loopqne))

# ------------------------------------------------------------
def is_call(insn):
    """Is a call instruction?"""
    return (insn.itype in CALL_INSTRUCTIONS) or idaapi.is_call_insn(insn)

def is_jcc(insn):
    """Is conditional branch?
    refer to intel.hpp/inline bool insn_jcc(const insn_t &insn)
    """
    return insn.itype in JCC_INSTRUCTIONS

def is_loop(insn):
    return insn.itype in LOOP_INSTRUCTIONS

def is_bp(insn):
    return insn.itype == idaapi.NN_int3

def is_ret(insn, strict=True):
    """Is the instruction a "return"?"""
    return idaapi.is_ret_insn(insn, strict)

def is_jmp_indirect(insn):
    """Is this an indirect jump?"""
    return idaapi.is_indirect_jump_insn(insn)

def is_jmp(insn):
    """Is this an indirect jump?"""
    return insn.itype == idaapi.NN_jmp

# ---------------------------------------------------------------------------
PF_NEW_CHUNK    = 0x01
PF_DISASM       = 0x02
PF_CHUNK_END    = 0x04
PF_NEXT_CHUNK   = 0x08
PF_OTHER        = 0x10
PF_CALLED_FUNCS = 0x20
PF_SPLIT        = 0x40
PF_STACK        = 0x80
PF_SEEN         = 0x100
PF_ALL          = 0xFFFF

# ---------------------------------------------------------------------------
class chunk_t:
    fl_is_ret  = 0x1
    fl_is_jmpi = 0x2
    fl_is_jcc  = 0x4
    fl_is_jmp  = 0x8
    fl_is_ud   = 0x10
    fl_is_bp   = 0x20

    def __init__(self, start, end, flags=0, target=0):
        self.start  = start
        self.end    = end
        self.flags  = flags
        self.target = target

    def __lt__(self, other):
        return self.start < other.start

# ---------------------------------------------------------------------------
def build_chunks(
        start_ea, 
        /,
        pf=0, 
        captured_calls=None, 
        ignore_errors=True, 
        max_blocks=-1, 
        bp_ends_block=False):
    """Given a supposed function start, return the function head and proper chunks"""
    seen_chunks = set()
    stack = [start_ea]
    chunks = []
    seen = set()
    instructions = {}

    iblock = 0
    while stack:
        chunk_start = ea = stack.pop()
        if chunk_start in seen:
            if pf & PF_SEEN:
                print(f" SEEN: {chunk_start:x}")
            continue

        seen.add(chunk_start)
        iblock += 1
        chunk_end = 0
        chunk_flags = 0
        chunk_target = 0

        if pf & PF_NEW_CHUNK:
            print(f"NEW_CHUNK #{iblock}: {chunk_start:x}")

        while True:
            inst = idautils.DecodeInstruction(ea)
            if inst is None:
                if ignore_errors:
                    chunk_flags |= chunk_t.fl_is_ud
                    break
                else:
                    return (False, f"{ea:x}: Failed to decode instruction")

            instructions[inst.ea] = (inst.itype, inst.size)
            # Each new instruction can be the end of a chunk
            ea = chunk_end = inst.ea + inst.size

            if pf & PF_DISASM:
                print(f"   {inst.ea:x} - {idc.GetDisasm(inst.ea)}")

            if captured_calls is not None and is_call(inst):
                captured_calls.append((inst.ea, inst.addr))
                if pf & PF_CALLED_FUNCS:
                    print(f"   CALL !:{inst.ea:x}")

            # Fall thru cases
            if is_jcc(inst):
                chunk_flags |= chunk_t.fl_is_jcc
                chunk_target = inst.Op1.addr

                # Two new chunks
                stack.insert(0, inst.Op1.addr)
                stack.insert(0, chunk_end)
                if pf & PF_NEW_CHUNK:
                    print(f"   EXPLORE {inst.Op1.addr:x}, FALLTHRU {chunk_end:x}")
                break
            # Loop
            elif is_loop(inst):
                print(f"untested...test me...")
                # Two new chunks
                stack.insert(0, inst.Op1.addr)
                stack.insert(0, chunk_end)
                if pf & PF_NEW_CHUNK:
                    print(f"   EXPLORE {inst.Op1.addr:x}, FALLTHRU {chunk_end:x}")
                break
            # No fall thru
            elif is_jmp(inst):
                chunk_flags |= chunk_t.fl_is_jmp
                chunk_target = inst.Op1.addr

                stack.insert(0, inst.Op1.addr)
                if pf & PF_NEW_CHUNK:
                    print(f"   EXPLORE {inst.Op1.addr:x}")
                break
            # BP instruction
            elif (bp_ends_block and is_bp(inst)):
                chunk_flags |= chunk_t.fl_is_bp
                if pf & PF_OTHER:
                    print(f"   --> BP {inst.ea:x}")
                break
            # RET does not generate new paths
            elif (b_is_ret := is_ret(inst)) or (is_ijmp := is_jmp_indirect(inst)):
                if b_is_ret:
                    chunk_flags |= chunk_t.fl_is_ret
                elif is_ijmp:
                    chunk_flags |= chunk_t.fl_is_jmpi

                if pf & PF_OTHER:
                    print(f"   --> {'RET' if b_is_ret else 'JMPI'} {inst.ea:x}")
                break

        # New chunk
        if chunk_end != 0:
            chunks.append(chunk_t(
                start=chunk_start, 
                end=chunk_end, 
                flags=chunk_flags, 
                target=chunk_target))
            if pf & PF_CHUNK_END:
                if pf & PF_STACK:
                    stack_str = "[STACK: " + ", ".join((f"{x:x}" for x in stack)) + "]"
                else:
                    stack_str = ''
                print(f"   >[{chunk_start:x} CHUNK #{iblock} END: {chunk_end:x}] {stack_str}")

        if max_blocks > 0 and iblock > max_blocks:
            break

    if pf & PF_OTHER:
        print(f'stack_len: {len(stack)}')

    return (True, (chunks, instructions))

# ---------------------------------------------------------------------------
def merge_chunks(chunks):
    start = 0
    repeat = True
    while repeat:
        repeat = False
        for i in range(start, len(chunks) - 1):
            a0, a1 = chunks[i  ].start, chunks[i  ].end
            b0, b1 = chunks[i+1].start, chunks[i+1].end
            # No overlap?
            if not (a0 <= b0 <= a1):
                start = i + 1
                continue
            # The next segment extends beyond the current, extend the current
            if b1 >= a1:
                chunks[i].end = b1
                chunks[i].flags |= chunks[i+1].flags

            # Since we had overlap, always delete the next one because we merged already
            del chunks[i+1]
            repeat = True
            break


# ---------------------------------------------------------------------------
del_chunk = lambda chunk: idaapi.del_items(chunk.start, 0, chunk.end - chunk.start)

# ---------------------------------------------------------------------------
def create_chunks(chunks, recreate_code=False, verbose=False, merge=True, ignore_errors=False):
    """Given the function stitching information, create proper head and tails"""

    # Before we merge, let's remember the function's start
    func_start = chunks[0].start

    if merge:
        merge_chunks(chunks)

    # After merge, the function initial range might have changed
    # We only care to find the range with the function's start and keep it the first check
    ichunk_start = -2
    for ichunk_start, chunk in enumerate(chunks):
        if chunk.start == func_start:
            break

    if ichunk_start == len(chunks) - 1:
        dump_chunks(chunks, banner="!!INTERNAL ERROR:", footer="<<<<<")
        return (False, "A previous chunk fallsthrough the function start. Revise the algorithm!")

    chunk = chunks[ichunk_start]
        
    del_chunk(chunk)

    # Always create the function first
    f = idaapi.get_func(chunk.start)
    if f is not None:
        idaapi.del_func(f.start_ea)
        if verbose:
            print(f"Deleting existing function {chunk.start:x}")

    if recreate_code:
        idaapi.create_insn(chunk.start)

    # ...create the function
    if verbose:
        print(f"{len(chunks)} chunks. creating function ({chunk.start:x}, {chunk.end:x})")

    if not idaapi.add_func(chunk.start, chunk.end):
        if not idaapi.set_func_end(chunk.start, chunk.end):
            return (False, "Failed to create function %x - %x" % (chunk.start, chunk.end))

    f = idaapi.get_func(chunk.start)
    if f is None:
        return (False, "Failed to retrieve function at %x" % chunk.start)

    f_ea = f.start_ea
    # Now create the tails for that function
    for ichunk, chunk in enumerate(chunks):
        if ichunk == ichunk_start: continue

        if verbose:
            print(f"#{ichunk} creating function tail ({chunk.start:x}, {chunk.end:x})")

        del_chunk(chunk)

        # See if there's a function where there should be a tail
        fchunk = idaapi.get_func(chunk.start)
        if fchunk:
            # See if that's not the same function parent
            if fchunk.start_ea != f_ea:
                # Delete the superfluous function
                idaapi.del_func(fchunk.start_ea)
                if verbose:
                    print(f"{chunk.start:x} deleting superfluous function that should be a tail")

        if recreate_code:
            idaapi.create_insn(chunk.start)

        if not idaapi.append_func_tail(f, chunk.start, chunk.end):
            if ignore_errors:
                continue
            return (False, f"Failed to create function tail ({chunk.start:x}, {chunk.end:x})")

    return (True, f_ea)

# ---------------------------------------------------------------------------
def dump_chunks(chunks, banner=None, footer=None):
    if banner:
        print(banner)

    for i, chunk in enumerate(chunks, start=1):
        print(f"#{i} {chunk.start:x} .. {chunk.end:x} [{chunk.flags:x}] -> {chunk.target:x}")

    if footer:
        print(footer)

# ---------------------------------------------------------------------------
def test(addr=0x180032701, do_stitch=False):
    global chunks, merged_chunks, instructions
    idaapi.msg_clear()

    f = idaapi.get_func(addr)
    if f:
        addr = f.start_ea

    #pf = PF_ALL & ~(PF_DISASM | PF_NEW_CHUNK | PF_SEEN)
    pf = PF_ALL
    ok, info = build_chunks(addr, pf=pf)
    if not ok:
        print(f'Error: {chunks}')
        return

    chunks, instructions = info

    dump_chunks(chunks, banner="***************chunks****************", footer="----------------")
    merged_chunks = copy.copy(chunks)
    merge_chunks(merged_chunks)
    dump_chunks(merged_chunks, banner="********merged chunks****************", footer="----------------")

    if do_stitch:
        ok, info = create_chunks(chunks, verbose=True, merge=False, recreate_code=True, ignore_errors=True)
        if not ok:
            print(f"error: {info}")
        else:
            print(f'{info:x} restored all chunks!')

# ---------------------------------------------------------------------------
if __name__=='__main__':
    test(do_stitch=True, addr=idc.here())

### 使用缝合脚本

光标放在 `start` 函数开头的 S U B R O U T I N E 的上面一行（该函数起始虚拟地址）

在 file $→$ Script file... $→$ 选择保存好的脚本

然后，那些碎尸会根据脚本 “缝合” 到一起。甚至是按 F5 都可以实现编译为 C 的伪函数。

简单的理解一下脚本要实现缝合的思路：函数头跟随跳转并连接，直到遇见 retn 结束。

其中，`start` 函数只有调用一个函数 `sub_18000853F`，查看该函数。

同理，在函数起始虚拟地址处再次执行脚本重编译。与 `start` 函数差不多也是只调用了一个 `sub_18003CEDE` 函数。而这个函数才是真正的第一个挑战。

### sub_18003CEDE 缝合

首先要能实现图形视图，依然是在函数起始虚拟地址处执行脚本。就实现了图形视图。不过这次是有报错且不可被转伪函数的。这时只需在报错的位置的函数起始虚拟地址再次运行脚本就可以实现转伪函数。但报错依然存在。

这因为是 **IDA 的栈指针分析** 和 **函数尾部创建时机** 之间的问题。

第二次 “标错误” 再运行就成功是因为 **IDA 的内部状态变了**。

```assembly
sub_18003CEDE:
sub     rsp, 0D08h      ; ① 分配了 0xD08 字节的栈空间
jmp     loc_18001BAC9   ; ② 直接跳走，没有 ret
sub_18003CEDE endp ; sp-analysis failed
```

这个函数只有两条指令：分配栈 + 跳转。它没有自己的 `ret`，而是跳到 `loc_18001BAC9` 去执行。

**第一次运行脚本时**，脚本执行流程是：

  1\. 删除原有函数，创建主函数 `sub_18003CEDE`。

  2\. 尝试将 `loc_18001BAC9` 所在的代码块作为“尾部”（Tail）附加进来。

**但是**，如果 `loc_18001BAC9` 这个地址在 IDA 中**还没有被识别为代码**（显示为 `db` 未定义数据，或者被识别为另一个孤立的函数），那么 `idaapi.append_func_tail()` 就会**静默失败**（因为脚本中有 `ignore_errors=True`）。

结果就是：`sub_18003CEDE` 只包含了开头的 `sub rsp, 0D08h` 和 `jmp`，而没有把跳转过去的那一大坨代码包含进来。

于是这个函数不完整，栈分配了 `0D08` 空间但函数内没有对应的释放（`add rsp, 0D08h`），IDA 分析时发现栈指针不平衡，直接报 `sp-analysis failed`，无法生成 C 伪代码。

**第二次运行脚本时**，IDA 发现 `loc_18001BAC9` 是一个合法的代码起始地址，且不与现有函数冲突。**这次尾部附加成功了**，`loc_18001BAC9` 的所有代码块被正确纳入 `sub_18003CEDE` 的函数体中。

栈指针平衡了，反编译器（F5）就能出 C 代码了。

但是，这个东西跳转来跳转去的依然是一个非常大的问题。

*后面的好复杂。不仅是涉及到代码编写的问题。就这道题只是对应着这样一段代码，那下一道题该如何自己写代码对抗代码混淆的问题。而且写代码并不是非常理想的解法，这种题的优解是控制流展平还原。这种题上网查几乎无果，不会有人写得这么清晰的。*

### 缝合脚本解析

**第 1 层：工具函数层**

告诉脚本“什么是跳转”、“什么是返回”、“什么是调用”。

```python
JCC_INSTRUCTIONS = set((idaapi.NN_ja, ...))  # 收集了所有条件跳转指令（ja, jb, je, jnz 等）
CALL_INSTRUCTIONS = set((idaapi.NN_call, ...)) # 收集调用指令
LOOP_INSTRUCTIONS = set((...))                # 收集循环指令
```

接着定义了 `is_call`、`is_jcc`、`is_ret` 等函数。它们都是对 IDA 底层指令对象的封装。

**第 2 层：数据结构与标志位**

定义 “碎片（Chunk）” 长什么样，以及调试时输出哪些信息。

```python
PF_NEW_CHUNK = 0x01   # 打印"发现新碎片"
PF_DISASM    = 0x02   # 打印每条反汇编
# ...等，它们可以用按位或（|）组合
```

`class chunk_t` 定义了一个碎片的属性：

- `start`：碎片的起始地址
- `end`：碎片的结束地址（最后一条指令的末尾）
- `flags`：标记这个碎片是以什么结尾的（`fl_is_ret` 返回、`fl_is_jmp` 跳转、`fl_is_jcc` 条件跳转……）
- `target`：如果结尾是跳转，跳转到哪里去

**第 3 层：核心算法 —— `build_chunks`**

  1\. **初始化**：从你指定的起始地址（`start_ea`）出发，把它放入一个 “待探索栈”（`stack = [start_ea]`）。

  2\. **循环探索**：只要栈里还有地址，就弹出一个（`chunk_start = stack.pop()`）。

  3\. **逐条反汇编**：从该地址开始，一条一条地解码指令（`idautils.DecodeInstruction`）。

  4\. **遇到分支就分裂**：

   - 如果遇到 **无条件跳转（`jmp`）**：当前碎片到此结束，把跳转目标地址 **压入栈**（待探索）。
   - 如果遇到 **条件跳转（`jcc`，如 `jz`、`jnz`）**：当前碎片到此结束，把 **跳转目标地址** 和 **下一行地址（fallthrough）** 都压入栈（产生两个新分支）。
   - 如果遇到 **返回（`ret`）** 或 **间接跳转（`jmp rax`）**：当前碎片到此结束，**不产生新分支**（路径终结）。

   5\. **记录碎片**：每次碎片结束时，把 `(start, end, flags, target)` 存进 `chunks` 列表。

**关键点**：它只负责“发现”碎片，并不修改 IDA 的函数结构。比如：`sub rsp... jmp loc_18001BAC9` 会被它识别为：一个从 `sub_18003CEDE` 开始的碎片，以 `jmp` 结尾，目标地址是 `loc_18001BAC9`。

**第 4 层：拼接执行 —— `create_chunks`**

它负责把上一步发现的碎片，真正写入 IDA 的数据库。

  1\. **定位主入口**：记住第一个碎片（`chunks[0]`）的起始地址作为函数头（`func_start`）。

  2\. **合并碎片**：如果 `merge=True`，调用 `merge_chunks` 把重叠的碎片合并。

  3\. **删除旧函数**：如果该地址已经存在函数，先用 `idaapi.del_func` 删掉。

  4\. **创建主函数**：用 `idaapi.add_func(chunk.start, chunk.end)` 创建函数框。

  5\. **循环拼接尾部：

   - 跳过第一个碎片（因为它已经是函数头了）。
   - 对于后面的每一个碎片：
     - 执行 `del_chunk(chunk)`（删除该地址上现有的 IDA 定义）。
     - 如果 `recreate_code=True`，执行 `idaapi.create_insn(chunk.start)`（尝试在这里创建指令）。
     - **最关键的一步**：执行 `idaapi.append_func_tail(f, chunk.start, chunk.end)`，把这个碎片挂载到主函数下面，成为它的“尾部”。
     - 如果挂载失败且 `ignore_errors=True`，**直接跳过，不报错**。

脚本 “失灵” 的根源就在最后这步。

```python
if recreate_code:
    idaapi.create_insn(chunk.start)   # ① 尝试把目标地址变成代码

if not idaapi.append_func_tail(f, chunk.start, chunk.end):  # ② 尝试挂载尾部
    if ignore_errors:
        continue  # ③ 失败了就静默跳过！
```

- 当脚本处理 `jmp loc_18001BAC9` 这个碎片时，`chunk.start` 就是 `0x18001BAC9`。
- 如果此时 `0x18001BAC9` 在 IDA 数据库里显示为 **未定义数据（`db`）** 或 **对齐填充（`align`）**，那么 ① 处的 `create_insn` 会**执行失败**（但它没检查返回值，所以脚本以为执行过了）。
- 紧接着 ② 处的 `append_func_tail` 要求目标地址必须是一条有效的指令开头。因为 ① 失败了，这里自然返回 `False`。
- 因为 `ignore_errors=True`，脚本默默地执行了 ③ `continue`，**这个尾部根本没挂上去**。

结果就是：函数只有开头的 `sub rsp... jmp`，没有跳转过去的那一大坨代码。IDA 分析时发现栈分配了 `0xD08` 空间却没对应释放，直接报 `sp-analysis failed`，**F5 自然转不了 C**。

而第二次执行脚本时（此时是在 `0x18003CEDE` 运行），`0x18001BAC9` 为有效的代码地址，脚本再跑时 `append_func_tail` 成功了，函数完整了，F5 就能用了。

### 整理碎尸

*暂时是没有看见有怎么写 y0da.bin 的思路*

整理碎尸需要在新地址生成一段**连续的、干净的**代码。直接在原 `.text` 节上修改会面临几个致命问题：

1\. **空间不够（容量问题）**：原始 `.text` 节的大小是固定的。重定位后的代码可能因为修复跳转偏移、填充 NOP 等操作变得比原来更大。强制写入会覆盖后面的数据，导致文件损坏。

2\. **环境太脏（残留问题）**：原始 `.text` 节里混杂着被混淆的垃圾指令、数据穿插和不对齐的地址。在你彻底验证新代码正确之前，保留原始代码作为“对照参考”是明智的选择。

3\. **权限灵活**：你可以在 PE-bear 里把新节设置为 `可执行(Execute)` + `可读(Read)`，方便 IDA 分析；如果需要运行时自修改，甚至可以勾上 `可写(Write)`，而不影响原始 `.text` 节的权限。

静态解析 new-y0da.exe 可以看到：前面保留了碎尸结构，后面才是整理完成的文件。

工具：PE-bear（GitHub）

用 PE-bear 打开 y0da.exe，在 区段 $→$​ 添加新节，选择编辑好的 y0da.bin 文件，并起一个名字，然后赋予它权限（正常情况下是都选）。

成功加入后还需要在可选头把 Entry Point （程序入口）修改成 `new_start` 函数的**映像基址的偏移量**，这样就可以安全地调试干净的程序了。

### 计算哈希值

本质上就是一个**“带大小写转换的循环右移累加器”**。把它拆成三个层次来看。

1\. 核心运算：ROR13（循环右移 13 位）

在代码里，虽然参数传的是 `(10, 3)` 或 `(8, 5)`，但因为：

- `_rotr(_rotr(hash, 10), 3)` 等价于 **整体循环右移 13 位**（10+3=13）。
- `_rotr(_rotr(hash, 8), 5)` 也等价于 **整体循环右移 13 位**（8+5=13）。

所以我们可以把这个底层操作简称为 **`ROR13(x)`**。

> **`ROR13` 在干什么？**
> 把 32 位数字的二进制位，像转盘一样整体往右推 13 格，右边溢出的 13 位补到左边。

2\. 两种处理模式（DLL 名 vs API 名）

代码里的模板参数 `as_unicode` 控制着两种截然不同的模式，这是理解哈希的关键：

| 对比项             | **DLL 名模式** (`as_unicode = true`)                         | **API 名模式** (`as_unicode = false`)             |
| :----------------- | :----------------------------------------------------------- | :------------------------------------------------ |
| **大小写处理**     | **强制转大写**（`if (c >= 'a') c -= 32;`）                   | **保持原样**（大小写敏感）                        |
| **每个字符处理**   | `hash = ROR13(hash) + c` **然后马上再 `hash = ROR13(hash)`** | `hash = ROR13(hash) + c` （**没有**后续额外旋转） |
| **字符串末尾处理** | 再额外做 **两次** `ROR13(hash)`                              | 只做 **一次** `ROR13(hash)`                       |

3\. 最终哈希 = DLL 哈希 + API 哈希

在 `hash_api` 函数里：

```c++
return hash_str<true>(dllname, 10, 3) + hash_str<false>(funcname, 8, 5);
```

**意思就是：把 DLL 名字的哈希值，和 API 函数名的哈希值，直接做 32 位加法（溢出丢弃）。**

**代入真实例子手算（验证 `0xE553A458`）**

我们用 `"KERNEL32.DLL"` 和 `"VirtualAlloc"` 来验证：

**第一步：算 DLL 哈希（`KERNEL32.DLL`）**

- 初始化 `hash = 0`。
- 遍历每个字符（注意因为强制转大写，你写 `kernel32.dll` 也一样）：
  1\. `hash = ROR13(hash) + 'K'` → 得到 `0x4B`
  2\. `hash = ROR13(hash)`（额外旋转）→ 得到一个很大的随机数
  3\. 重复直到字符串末尾。
- 遍历结束后，再额外旋转 **两次** `ROR13`。
- 最终得到某个值（记为 `dll_hash`）。

**第二步：算 API 哈希（`VirtualAlloc`）**

- 注意大小写敏感：`'V'` 和 `'v'` 算出来不一样，这里必须用 `"VirtualAlloc"`（首字母大写，其余小写）。
- 初始化 `hash = 0`。
- 遍历每个字符：
  1\. `hash = ROR13(hash) + 'V'` → 得到 `0x56`
  2\. **没有额外旋转**，直接处理下一个字符。
- 遍历结束后，只旋转 **一次** `ROR13`。
- 最终得到 `api_hash`。

**第三步：相加**

- `dll_hash + api_hash = 0xE553A458`（这正是你汇编里看到的 `api_VirtualAlloc` 的值）。

**一句话理解：所有 `api_xxx` 的值，都是“DLL 哈希 + 函数名哈希”的组合和**。只要看懂了这段 C++ 代码，就能把任何函数名手动算出哈希值，并在 IDA 中建立枚举，将神秘数字换成人类可读代码。
